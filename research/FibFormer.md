# FibFormer

A research-grade deep learning system that fuses Fibonacci-based trading heuristics with a Temporal Fusion Transformer to forecast Indian index derivatives direction, pivot levels, and market regime across multiple time horizons.

---

# Elevator Pitch

FibFormer is an end-to-end quant research platform that asks a specific question: can the tacit knowledge of a proprietary trading heuristic be encoded into a differentiable neural architecture? The project takes two hand-crafted Fibonacci price-action scripts — impulse trigger logic and anchor cluster logic — and rather than using them as hard rules, it ports them into a learnable layer that the model trains alongside everything else. The result is a system that starts with human expert intuition and then learns when and how much to trust it.

The system is built for quant researchers and systematic traders focused on BankNifty and Nifty — India's most liquid index derivative contracts. It addresses a real gap: pure deep learning models ignore domain knowledge entirely, while rule-based systems can't adapt to regime change. FibFormer occupies the middle ground, combining SSA signal denoising, FinBERT sentiment fusion, and a Gated Cross-Modal Attention mechanism that biases attention toward Fibonacci-aligned price regions.

What makes it different is the statistical rigor applied to the outputs. The model's backtest is validated using the Deflated Sharpe Ratio (Bailey & López de Prado, 2014), which penalizes for non-normality, short history, and multiple testing. Predictions are explained through SHAP attribution, and regime shift is monitored in real time via KL divergence drift detection. This is not a demo — it's the kind of system that could plausibly appear in a quantitative finance research paper, and the repository includes a BibTeX citation for a paper under IEEE review.

The full system ships as a containerized product: a FastAPI backend, a React quant terminal dashboard with live streaming narrative via Ollama, and a Docker Compose deployment that brings everything up in a single command.

# Product Overview

FibFormer is a quant terminal for index futures traders and researchers. The primary user is someone who already understands Fibonacci price-action methods and wants a model that can formalize, validate, and scale those methods using deep learning.

The core workflow begins with live market data fetched from Yahoo Finance for BankNifty or Nifty. That data passes through an SSA denoiser (Singular Spectrum Analysis) to strip noise from price signals, then through two expert feature engines that compute Fibonacci confluence levels, impulse gate scores, anchor cluster proximity, and temporal anchor age. The enriched feature set is fed into the FibFormer model, which outputs direction signals at three horizons (t+1, t+4, t+8), a predicted pivot level, and a market regime classification.

On the frontend, a dark-mode quant terminal displays a candlestick chart with live Fibonacci reference lines overlaid, a signal panel showing directional conviction across all three horizons, a SHAP attribution visualization showing which features drove the signal, a drift alert banner if market behavior has diverged from the training distribution, and a backtest panel where the user can trigger a walk-forward simulation and view DSR-validated performance metrics.

The narrative feature lets the user click "Explain" and receive a streamed, grounded plain-English interpretation of the signal generated by a local LLM (Ollama, Qwen2.5 or Llama-3). The prompt is tightly constrained to prevent hallucination — the model is only permitted to speak to the data that was actually computed.

Real-world use cases include pre-market signal review for BankNifty traders, regime-aware position sizing, and research into whether Fibonacci heuristics carry statistically significant predictive signal after controlling for overfitting.

# Problem Statement

Technical traders working with Indian index derivatives often rely on proprietary Fibonacci-based rules to identify impulse candles, support/resistance clusters, and retrace levels. These rules work well in some regimes and fail silently in others. There is no principled way to know when to trust them, how much weight to give any one level, or when the market has shifted into a regime where the rules break down entirely.

Existing solutions are insufficient in both directions. Pure ML models discard this domain knowledge entirely, treating it as noise, and they tend to overfit short financial time series without proper statistical validation. Rule-based systems, on the other hand, are brittle — they have no mechanism to learn from data, adapt to changing conditions, or quantify their own uncertainty.

FibFormer solves this by making the heuristic itself differentiable. The [130, 160] impulse range gate becomes a learned sigmoid. The ±10 tick proximity threshold becomes a learnable scale factor. The historical anchor is discounted by a learned exponential decay. The model learns when the heuristic is reliable and when to ignore it, trained end-to-end on labeled BankNifty data.

# Key Features

## Expert-Informed Deep Learning
The Differentiable Heuristic Layer (DHL) is the architectural core of the project. It takes the hard-coded rules from two Fibonacci trading scripts and replaces their discrete gates with continuous, trainable parameters. This is not feature engineering — the model learns the gate itself. The result is a neural architecture where the expert's knowledge is a prior, not a constraint.

The Gated Cross-Modal Attention mechanism extends this by injecting a Fibonacci proximity bias directly into the attention score matrix. Timesteps where price is close to a historically validated Fibonacci cluster receive higher attention weight during training. This forces the model to learn in a way that is structurally consistent with the underlying price-action theory.

## Multi-Horizon Signal Generation
The model outputs directional predictions at three horizons simultaneously: t+1 (next bar), t+4 (four bars forward), and t+8 (eight bars forward). A high-conviction flag is set when the t+1 and t+4 predictions agree on a non-flat direction above a confidence threshold. This mirrors how experienced traders filter signals — a single-horizon prediction is less actionable than a consistent directional view across multiple timeframes.

## Statistical Validation via Deflated Sharpe Ratio
The backtest endpoint does not just compute a Sharpe ratio. It implements the Bailey & López de Prado (2014) Deflated Sharpe Ratio, which penalizes the reported alpha for the skewness and kurtosis of the return stream, the length of the backtest, and the number of hyperparameter configurations tested during research. A DSR that remains significant after these corrections is a much stronger claim than a raw Sharpe. The system surfaces whether the result clears the 95% confidence threshold.

## Explainability via SHAP Attribution
Every inference call computes a surrogate SHAP attribution over the 24-dimensional expert feature vector. This tells the user which Fibonacci proximity or impulse gate feature most influenced the current signal. The frontend renders this as a ranked bar chart. The narrative endpoint then feeds these attributions directly into the LLM prompt to produce grounded, non-hallucinated explanations.

## Regime-Aware Drift Monitoring
A KL divergence drift detector runs continuously against the live feature distribution, comparing it to the reference distribution from training. When drift exceeds a threshold, the system emits a severity-graded alert — mild, moderate, or severe — with a natural language warning. This prevents the model from being trusted in market conditions that differ meaningfully from what it was trained on.

## Local LLM Narrative Streaming
The narrative endpoint uses Ollama to stream a quantitative analyst commentary grounded in the actual model outputs. The prompt is engineered to prevent the LLM from inventing values: it can only describe the directions, confidence, regime, SHAP features, and drift state that were computed by the model. The stream is delivered via Server-Sent Events so the text appears token by token in the UI.

## Adversarial Robustness Training
During training, 50% of batches receive FGSM (Fast Gradient Sign Method) perturbation applied specifically to the Fibonacci proximity features. This tests and enforces the claim that the model's structural reliance on Fibonacci information is genuine and not a fragile correlation. The adversarial training is reported in the research paper as a robustness validation.

## Walk-Forward Backtesting
The backtest endpoint runs a proper walk-forward simulation — it never shuffles the time series, never peeks at future data, and applies a trade gate that only takes positions when the H4 direction is confident. The result includes total return, max drawdown, Calmar ratio, Sharpe, DSR, win rate, and information coefficient, along with a rendered equity curve in the UI.

# Engineering Highlights

The backend is a FastAPI application with three main endpoints: a forecast endpoint that fetches, denoises, featurizes, and runs inference on live market data; a Server-Sent Events endpoint that streams LLM-generated narrative; and a backtest endpoint that runs a full walk-forward simulation. The backend uses a 60-second in-memory cache to avoid redundant data fetches on repeated requests and gracefully degrades to demo mode when the model checkpoint is unavailable.

The ML engine is fully modular: feature engineering, denoising, labeling, model, training, inference, and drift detection are each isolated packages with their own init files. The training pipeline uses expanding-window temporal cross-validation (never shuffle), AdamW with cosine annealing, gradient clipping, early stopping, and epoch-level checkpointing. The loss function is a multi-task weighted cross-entropy with label smoothing, class-weighting to penalize FLAT predictions, and Huber regression loss for pivot level prediction.

The frontend is a React single-page application using Recharts for the candlestick chart and backtest equity curve. It polls the forecast endpoint every 60 seconds, renders Fibonacci reference lines at the correct price levels on the chart, and manages the SSE stream lifecycle for the narrative feature. The design is a custom dark-mode quant terminal theme built with CSS variables.

The deployment is fully containerized with Docker Compose. The backend service depends on both Ollama and Redis. Health checks are configured on the backend container. The frontend is served through Nginx in production. Redis is included for caching, and Ollama runs as a sidecar with a persistent volume for model weights. GPU support for Ollama is commented in but ready to enable.

The test suite covers the ML engine with 20 unit tests including a dedicated adversarial robustness test that verifies FGSM perturbation behavior.

# AI / ML Components

The central model is FibFormer, a custom PyTorch architecture that combines a Differentiable Heuristic Layer, an Expert Embedder, a Sentiment Projector for FinBERT embeddings, Gated Cross-Modal Attention, a Temporal Fusion Transformer backbone (LSTM + Gated Residual Network + multi-head self-attention with sinusoidal positional encoding), and three output heads — direction (classification, 3 horizons), pivot level (regression), and regime (classification).

Training uses multi-task learning with a weighted loss function that discourages the model from defaulting to FLAT predictions. FGSM adversarial training is applied to Fibonacci proximity features specifically, making the model's reliance on expert knowledge structurally robust.

The FinBERT sentiment stream is architected into the model as a first-class input. When headline sentiment embeddings are unavailable, the sentiment stream passes zeros through a masked projector. The architecture is ready to accept real FinBERT CLS embeddings without modification.

SHAP attribution is computed at inference time using a surrogate ablation approach — each expert feature is zeroed out and the change in prediction logit is measured. This is not approximate SHAP but a principled feature importance method that operates in logit space for higher sensitivity.

The narrative system uses Ollama running locally (Qwen2.5-coder:7b or Llama-3.2) with a structured prompt that injects computed model outputs and prohibits the LLM from introducing information not present in the signal. This is a form of grounded generation designed to make the LLM a communicator of the model's outputs rather than an independent forecaster.

# Data Engineering / Data Science Components

Raw OHLCV data is fetched from Yahoo Finance at 1-hour intervals using yfinance. The data passes through Singular Spectrum Analysis (SSA) denoising with window length 48 and 6 components, using the pyts library, to produce smoothed price series used as model inputs alongside the original prices.

Feature engineering is divided into two pipelines ported from proprietary trading scripts. The ImpulseTriggerFeatures pipeline computes anchored support/resistance levels that only update on qualifying impulse candles, breach flags, a soft impulse gate score, and ATR-normalized proximity to anchored levels. The AnchorClusterFeatures pipeline performs a lookback scan for each bar to find the closest historical Fibonacci projection within a proximity window, computing signed distance and anchor age for four multiplier levels and two sides (RC/FC), yielding 16 proximity and age features.

Labels are generated using the Triple Barrier Method — a standard technique in quantitative finance that assigns directional labels based on which barrier (upper, lower, or time) is hit first within a forward window. This avoids the lookahead bias that plagues simpler labeling approaches.

The processed data directory contains 5-fold train/validation splits generated by the temporal cross-validation pipeline, along with the denoised series, full feature matrix, labeled dataset, and summary statistics. Model checkpoints are saved per epoch with a rolling "best" checkpoint updated on validation accuracy improvement.

The backtest system computes the information coefficient as the Spearman rank correlation between predicted and actual directions — a standard predictive accuracy metric in quant research. The DSR implementation follows the exact formula from Bailey & López de Prado (2014) with proper handling of the denominator sign edge case and dimensionally consistent per-bar Sharpe computation.

# Product Thinking

FibFormer demonstrates several product decisions that reflect genuine user research and workflow thinking.

The choice to support a demo mode when the model checkpoint is unavailable shows onboarding thinking — a new user who clones the repository and starts the server sees a working UI immediately, not an error page. The demo mode returns plausible-looking signals that make the product self-explanatory before the model is trained.

The 60-second auto-refresh and the explicit Refresh button give the user two interaction modes: passive monitoring and active investigation. The chart shows the last 80 bars by default, which is enough context to see the current Fibonacci levels in relation to recent price action without overwhelming the display.

The high-conviction flag is a product decision, not an engineering one. Rather than showing raw confidence numbers and expecting the user to interpret them, the system synthesizes agreement across horizons into a binary flag with a clear visual indicator. This reduces cognitive load for the primary use case: deciding whether to act on a signal.

The drift alert is positioned prominently at the top of the UI, above the main content, because it is the most important piece of information for risk management. A signal in a drifted regime should be discounted regardless of its confidence score. Surfacing this as a banner rather than burying it in a statistics panel reflects an understanding of how traders actually use alerts.

The narrative feature addresses the trust problem in ML forecasting systems. Traders are unlikely to act on a signal they cannot interpret. By providing a grounded, three-sentence explanation generated from the actual model outputs, the system reduces the black-box effect without requiring the user to understand SHAP values or attention weights directly.

The decision to validate with DSR rather than raw Sharpe is a product decision aimed at a sophisticated audience. Quant researchers are aware of backtest overfitting. Showing a DSR that is statistically significant at 95% confidence signals that the builder understands the critique and has addressed it — this builds credibility with the intended user.
